## 2차 리뷰 반영 (2026-08-15) — 참조 체계 정리

두 번째 외부 리뷰(커밋 79ce45d)가 배치 2의 결함을 지적했다. Claude가 코드로
검증한 결과 **핵심 3건이 사실이었고, 그중 하나는 배치 2에서 새로 만든
결함**이다.

- **NEXT 중복 (내가 만든 결함).** `--ref-character`와 `--ref-chain`을 함께
  쓰면 설명이 둘 다 "The NEXT attached image"로 나와 어느 첨부가 어느
  역할인지 무너진다. 가정이 아니라 **제작대장 이미지 G(시트+x5+CS)에서
  실제로 발생**한다. 배치 2 검증에서 단일 조합만 보고 다중 조합을 안 봤다
- **표준 문서의 SECOND·THIRD 하드코딩.** WOMAN·CONTINUITY 원문이 고정
  첨부 조합을 전제한다. 우리는 컷마다 조합이 다르다
- **check_clips 오디오 None → TypeError** (106행은 None을 검사하는데
  115행이 그대로 포맷)

**`--ref-chain` 확대 제안은 철회했다.** 리뷰 논거가 맞다 — 분류 축은
"어디서 만든 이미지인가"가 아니라 **"무엇을 승계하는가"**다. G→K는 각도만
가져오고 조명·기미·표정은 버려야 하는데 chain의 "same lighting, same
materials"가 정반대다. 그대로 갔으면 첨부 설명과 프롬프트 제외 목록이
싸우는, 이미 아는 실패 모드를 스스로 만들었을 것이다.

### 리뷰 지적 중 반영하지 않은 것과 이유

- **캐릭터 시트 CLI 승인 검사(fail-open)**: 승인은 사람의 눈 판단이고,
  상태 파일을 만들면 그것도 동기화 대상이 된다 (이번에 진행상태·제작대장·
  PLAN 세 곳이 어긋난 게 정확히 그 문제였다). 방어선은 "생성 전 제작대장
  확인"이다
- **엑셀 생성기가 output/ 안**: 생성기는 편별 데이터가 박힌 스크립트라
  편마다 새로 쓰는 게 정상이다. 재현 대상은 레이아웃 규칙이고 그건
  scene-design.md에 있다. 다만 본보기 포인터가 gitignore 안을 가리키는 건
  사실이라, 데이터 없는 골격을 스킬에 두는 것은 백로그
- **일부 클립만 있어도 성공**: check_clips는 "있는 것을 검사"하는 도구이고
  기대 개수는 제작대장이 안다. 회수 시 대장 대조가 본래 절차
- **A·D·F1 프롬프트 정합화**: 새 표준으로 전부 다시 쓰므로 불필요
