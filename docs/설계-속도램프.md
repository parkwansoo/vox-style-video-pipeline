# 설계 — 클립 내 구간별 속도 램프 (가변 배속)

2026-08-17 사용자 승인. TODO "클립 내 구간별 속도 램프" 항목의 구현 설계.

## 문제

assemble.py는 클립당 균일 배속(`setpts=PTS/rate`)만 지원한다. 그래서 한
클립 안에서 중요한 비트에 시간을 몰아줄 수 없다:

- clip1a: 4.06x 균일 → 끝의 광대 매크로(가장 중요)가 0.4초 만에 지나간다
- clip5: 1.47x 균일 → 끝의 기미 퍼짐이 너무 빨리 전환된다

사용자 요구는 AE의 이지 키프레임 수준 부드러움. 2조각 하드 분할(9x→1.5x)은
경계에서 속도가 6배 점프해 뚝 끊겨 보인다 — **이징이 설계의 핵심이다.**

## 원리 — AE 이지 이즈의 재현

AE의 시간 리맵도 결국 "부드러운 속도 곡선을 출력 프레임마다 샘플링"이다.
같은 것을 ffmpeg로 만든다:

1. 사용자는 **키프레임 2~4개**만 쓴다 (소스 구간 → 출력 길이)
2. 스크립트가 경계 주변을 **smoothstep 곡선을 따라 미세 조각으로 자동
   전개**한다 (조각당 출력 ~0.1s)
3. 조각들을 trim+setpts / atrim+atempo로 잘라 concat — **한 번의 인코드**

수학적 근거: 대칭 smoothstep 전이는 적분(소비하는 소스 길이)을 계단 함수와
정확히 같게 보존한다. 즉 이징을 아무리 넣어도 **소스 총량·출력 총량이
변하지 않아** 나레이션 싱크가 유지된다.

## manifest 인터페이스

```json
{"file": "clip1a.mp4", "seg_start": 0.0, "seg_end": 1.48,
 "ramp": [
   {"src": [0.0, 4.5],   "dur": 0.50},
   {"src": [4.5, 6.016], "dur": 0.98}
 ],
 "ease": 0.3}
```

- `ramp[i].src`: 소스에서 쓸 구간(초). 인접 구간은 이어져야 한다
- `ramp[i].dur`: 그 구간이 출력에서 차지할 길이. 배율은 자동 = src폭/dur
- `ease`: 경계 전후 가감속 폭(출력 초). 생략 시 0.3. 0이면 하드 스텝
- `ramp`가 있으면 그 클립의 `in`/`out`/자동 배속 맞춤을 **대체**한다
  (in=첫 src, out=끝 src, 출력 길이=dur 합계)

## 구현 (assemble.py)

**expand_ramp(ramp, ease, fps) → [(src_in, src_out, out_dur), ...]**

1. 검증: src 연속성, 각 구간 배율 ≥ 1.0 (슬로모는 에러로 거부 — 프레임
   합성은 별개 문제), ease를 인접 구간 길이의 절반 이하로 클램프
2. 출력 시간축 위에 속도 프로파일 v(t)를 만든다: 구간 내부는 상수, 경계
   ±ease/2는 smoothstep 전이
3. 수치 적분(dt = 1/(4·fps))으로 누적 소스 위치 s(t)를 얻고, 전이 창은
   ~0.1s 간격, 상수 구간은 통짜로 분절점을 뽑는다. 마지막 점을 소스 끝에
   강제 정렬해 부동소수 오차를 흡수한다
4. 조각별 실제 배율 = Δsrc/Δout — 총량 보존이 구조적으로 보장된다

**클립 정규화 경로 분기**

- ramp 없는 클립: 기존 경로 그대로 (`-ss/-t` + `-vf`) — **회귀 없음**
- ramp 있는 클립: `-filter_complex` 한 방으로
  - 영상: `[0:v]trim=A:B,setpts=(PTS-STARTPTS)/r[vi]` × N → `concat` →
    기존 체인(delogo → fit/zoom/shake → format)을 뒤에 연결
  - 오디오: `[0:a]atrim=A:B,asetpts=PTS-STARTPTS,atempo…[ai]` × N →
    `concat` — **음소거하지 않는다** (사용자가 듣고 판단, 2026-08-17 결정).
    atempo는 기존 atempo_chain() 재사용 (2.0 초과 배율 분해)
  - zoom/shake의 nf는 dur 합계 기준, delay 로직 동일

**검증·기록**

- dur 합계와 나레이션 구간(+뒤 xfade)이 0.05s 이상 어긋나면 경고
- `--max-rate` 경고는 ramp 클립에 적용하지 않는다 (배율이 명시적 의도)
- timeline.json에 전개된 조각 목록(src/out/rate)을 기록해 실물 대조 가능

## 하지 않는 것 (경계)

- 1.0x 미만 슬로모 (minterpolate 프레임 합성은 아티팩트 위험 — 필요해지면
  별도 검토)
- 합성 모션 블러 (소스 렌더에 이미 구워져 있음. 스트로브가 거슬리면 tmix
  후보 — 실물 보고 판단)
- Remotion (08-03 실측: playbackRate는 setpts와 동일, 이득 없음)
