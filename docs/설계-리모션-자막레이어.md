## 20번 차용 원칙 (미래 통합 대비 — 사용자 요청)

**"데이터 계약은 20번과 동일하게, 렌더러는 최소로."** 통합 시나리오는 이미
검증됐다: 28번을 20번에 합치는 날이 오면 `subtitler/`를 버리고 20번 remotion을
그대로 쓰면 된다(이번 테스트가 그 구성이었다). 그날까지 지켜야 할 계약:

1. **captions.json 스키마 동일**: `[{text, startMs, endMs}]` (20번 captionSchema)
2. **props 한글 키 동일**: 비율·폰트·글자굵기·글자크기·글자색·외곽선색·외곽선두께·
   강조색1/2·등장효과·효과세기·자막높이·안전여백·자막최대너비·자막목록·장면목록·
   영상길이ms — 20번 `remotion/schema.ts`와 같은 이름 사용
3. **프리셋 형식 동일**: 20번 `config/video-presets.json` 형식(영어 키 + ratioOverrides).
   통합 시 우리 프리셋을 그 파일에 항목 하나로 넣으면 끝
4. **폰트 경로 규약 동일**: publicDir 아래 `_fonts/<파일>` — 20번 fonts.ts가 무수정 작동
5. **컴포넌트 무수정 이식**: Captions.tsx·caption-layout.mjs·fonts.ts·font-catalog.mjs를
   **강조 로직 포함 그대로** 복사한다. 강조는 `강조단어: []`로 끈다(제거 아님).
   diff가 없을수록 검증된 동작이 유지되고 통합·역기여가 쉽다

## 테스트에서 배운 것 → v2 반영 사항

1. **defaultProps 미전달 함정** (실사고): Remotion은 inputProps에 없는 키를
   defaultProps로 채운다. 20번 스튜디오 잔여값(16:9용 자막최대너비 68)이 우리
   자막을 734px로 조였다. → **렌더 스크립트가 모든 prop을 항상 완전 명시 전달**,
   defaultProps는 active-input.json import 참조(스튜디오 검수용일 뿐)
2. **화질**: 기본 CRF 18(8.7Mbps)은 HEVC 14.3Mbps 원본 대비 아깝다. →
   `--crf` 옵션 기본 **14**(사용자: 화질 우선), `--codec` h264 기본·h265 선택
3. **fps·해상도 가변**: 원본 final.mp4(720x1280@24)와 외부 업스케일본
   (1080x1920@30) 둘 다 자막 대상이 된다(0804 사례). → 렌더 스크립트가 입력
   영상을 ffprobe로 재서 가로/세로/fps를 props로 전달, calculateMetadata가 그대로 사용
4. **폭 예산 자동화**: make_captions의 `--font-px 91 --avail-px 930` 하드코딩을
   timeline.json(width/height)+프리셋(pct)에서 자동 계산으로 교체
5. **재합본 후 자막 재생성 필수** (offset이 변하므로) — SKILL 7.5에 명기

## 남은 구현 (subtitler/ 렌더러)

### 1. 스캐폴드
```bash
cd "…/28_100% Automated Vox"
npx create-video@latest --yes --blank --no-tailwind subtitler
```
- zod는 설치된 Remotion이 내장 요구하는 버전으로 고정 (4.0.484 기준 4.3.6),
  `@remotion/fonts` 추가, `npx remotion versions`로 경고 0 확인
- 루트 `.gitignore`에 `subtitler/node_modules/` 추가. 폰트 .otf는 커밋

### 2. 20번에서 무수정 복사
| 원본 (`20_숏츠 자동화/`) | 대상 |
|---|---|
| `remotion/Captions.tsx` | `subtitler/src/Captions.tsx` (import 경로만 조정) |
| `remotion/caption-layout.mjs` (+`.d.mts`) | `subtitler/src/` |
| `remotion/fonts.ts` | `subtitler/src/fonts.ts` |
| `remotion/font-catalog.mjs` (+`.d.mts`) | `subtitler/src/` (파일은 G마켓산스만 동봉, 카탈로그는 전체 유지) |
| `outputs/audio/_fonts/GmarketSansBold.otf` | `subtitler/assets/fonts/` |

### 3. 신규 작성 (최소)
- `subtitler/src/schema.ts` — 20번 schema.ts의 자막 관련 서브셋, **키 이름 동일**.
  장면목록은 `[{startMs, endMs, type:'video', asset, volume}]` 단일 배경 영상용 축소판
- `subtitler/src/SubtitledVideo.tsx` — AbsoluteFill > OffthreadVideo(volume 1, cover)
  + Captions (20번 CaptionVideo.tsx의 bg-video 경로만 남긴 축소판)
- `subtitler/src/Root.tsx` — Composition id **'CaptionVideo'**(20번과 동일),
  calculateMetadata: props의 가로/세로/fps 사용, defaultProps = active-input.json import
- `subtitler/config/caption-preset.json` — 20번 프리셋 형식:
  ```json
  {"vox-기본": {"fontKey":"G마켓 산스","fontWeight":800,"fontSizePct":4.74,
   "textColor":"#FFFFFF","strokeColor":"#000000","strokeWidthPx":5,
   "entrance":"fade+pop","effectStrength":1,"captionYPct":65,
   "safeMarginPct":6,"captionMaxWidthPct":88}}
  ```
  (strokeWidthPx는 1080 기준 5 — 720 렌더 시 스크립트가 높이 비례 축소)
- `subtitler/scripts/render.mjs` — 20번 render-video.mjs:110-161 미러 + 개선:
  - CLI: `--run output/<run>` `[--video final.mp4]` `[--out final_sub.mp4]`
    `[--preset vox-기본]` `[--crf 14]` `[--codec h264|h265]`
  - 입력 영상 ffprobe(가로/세로/fps/길이) → props 완전 구성(강조단어 [] 포함 전 키)
  - 스테이징 publicDir: `<run>/.subtitle-public/`{bg.mp4, _fonts/}
  - bundle → selectComposition('CaptionVideo') → renderMedia(crf, codec)
  - 원자적 발행(임시명 → rename, 기존본 .prev 백업) + PROGRESS % 로그
  - 자체 검증: 오디오 스트림·길이 ±0.15s·해상도·fps 일치, 실패 시 비정상 종료
- `make_captions.mjs` 소폭 수정: 폭 예산을 timeline.json+프리셋에서 자동 산출
