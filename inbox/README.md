# 작업 투입함 — 대본(필수) + 음성(선택)

두 가지 모드가 있다. `대본.txt`를 채우고 "인박스 파일로 시작해줘"라고
말하면 음성 파일 유무로 자동 판별한다.

| 넣은 것 | 흐름 |
|---|---|
| **대본만** | TTS로 음성을 생성한다 (기본 파이프라인 3단계 그대로 — **배속은 활성 스타일의 권장값을 tts.py가 자동 적용**, 보이스 지정 가능, 음량 균일화 자동) |
| **대본 + 음성 1개** | 가져온 음성을 그대로 쓴다 (합성만 건너뛰고 무음 압축·정렬은 동일) |

음성 지원 형식: WAV, MP3, M4A, AAC, FLAC, OGG, OPUS.

아래 절들은 **음성을 가져오는 경우**에 해당한다. 대본만 넣으면 신경 쓸 것
없이 대본 품질(2단계 규칙)만 지키면 된다.

## 통짜 한 파일로 넣는다

나레이션 오디오가 하나면 **챕터도 하나**다. `assemble.py`에서 챕터는
"이 클립이 어느 나레이션의 어느 구간을 쓰는가"를 묶는 그룹일 뿐이라,
파일이 하나면 나눌 이유가 없다. 챕터를 쪼개면 manifest를 여러 개 만들고
경계에서 프레임을 승계하는 수작업이 늘어난다.

챕터를 나누는 게 맞는 경우는 셋뿐이다 — 목소리가 중간에 바뀔 때, TTS를
나눠 만들어야 할 사정이 있을 때, 한 구간의 나레이션만 따로 재생성할 때.

## 대본은 실제 발화와 일치해야 한다

대본은 자막의 정본이자 무음 압축의 문장 경계 판정 근거다. 음성이 대본과
다르게 읽혔으면 정렬률이 떨어지고, 그러면 자막 타이밍과 무음 압축이 함께
흔들린다. TTS 입력으로 쓴 텍스트를 그대로 넣는 게 가장 안전하다.

표현태그(`[sighs]` 등)를 넣어 합성했다면 **태그를 뺀 순수 대본**을 넣는다.
태그는 대본에 없는 소리라 정렬로 위치를 잡을 수 없고, 무음 압축이 한숨을
잘라낼 수 있다. 그런 음성은 압축을 끄는 편이 안전하다.

## 들어오면 이렇게 흐른다

1. 읽기 전용 검사 — 대본이 UTF-8·비어 있지 않은지, 음성에 유효한 스트림이
   있는지, 음성이 정확히 하나인지. 실패하면 **입력을 건드리지 않고 멈춘다**
2. 통과분만 `output/<날짜-슬러그>/ch1/`로 이동
3. 무음 압축 → ASR → 대본 정렬 → `words.json`
4. 여기부터는 기존 파이프라인 그대로 (클립 분할 설계 → 이미지 → 영상 → 합본)

3번까지 끝나면 정렬률과 무음 압축 통계를 보고한다. 정렬률이 낮으면 대본을
실제 발화에 맞춰 고치고 다시 돌린다.
