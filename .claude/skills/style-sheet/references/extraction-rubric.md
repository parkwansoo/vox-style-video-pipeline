# 레퍼런스 이미지에서 무엇을 관찰할 것인가

레퍼런스 이미지를 볼 때 이 순서로 관찰한다. 각 항목은 [slot-template.md]의
슬롯 하나에 대응한다.

## 대원칙 — 소재와 스타일을 가른다

**여러 장에서 반복되는 것만 스타일이다.** 한 장에만 있는 것은 그 이미지의
소재이지 시각 시스템이 아니다.

- 세 장 모두에 하프톤 인물 컷아웃이 있다 → **스타일** (COMPONENT ZOO에 넣는다)
- 한 장에만 배가 있다 → **소재** (버린다)
- 두 장에 찢어진 종이 가장자리가 있다 → **스타일** (경계선이지만 채택)

판단 기준: 레퍼런스 N장 중 **과반(N=2면 2장, N=3~4면 2장 이상, N=5면 3장 이상)**에
나타나면 채택한다. 애매하면 버린다 — 시트에 잘못 들어간 요소는 이후 모든
이미지 생성을 오염시킨다.

한 장에만 있지만 **명백히 시스템의 일부**로 보이는 것(예: 유일하게 등장한
지도 핀이지만 다른 요소들과 제작 논리가 동일)은 채택하되, DNA JSON의
`confidence`에 낮음으로 표기한다.

## 관찰 순서

### 1. 표면 (③) — 배경에 무엇이 깔려 있는가

이미지의 **빈 공간**을 본다. 피사체가 아니라 그 뒤에 깔린 바탕.

- 재질: 종이 / 청사진 / 스튜디오 배경지 / 캔버스 / 금속 / 없음(순색)
- 질감: 그레인 / 격자 / 얼룩 / 매끈함
- 색조: 균일한가, 그라데이션인가 (그라데이션이면 방향까지)

한 문장으로 쓴다: `aged archival paper / muted map texture field, visible grain and print texture`

### 2. 분위기 (④) — 세 단어로

이미지를 3초만 보고 떠오르는 인상. 형용사 3~4개.
서로 모순되는 단어를 섞지 않는다(`calm` + `chaotic` 금지).

기준 예: `precise, technical, draftsman-calm` / `newsroom-serious, layered, tactile, slightly retro` / `friendly, tactile, toy-like, calm`

### 3. 팔레트 (⑥⑦) — 스크립트 + 눈 병행

`extract_palette.py` 결과를 **먼저 읽고**, 그 다음 이미지를 본다.

스크립트가 주는 것:
- `hex` — 정확한 색값 (눈대중 금지)
- `coverage` — 화면 점유율. 20% 넘으면 주조색, 10% 미만이면 강조색
- `edge_ratio` — 높으면(0.45+) 선·윤곽에만 쓰이는 색
- `shared` — false면 그 이미지만의 소재색이므로 **버린다**

내가 판단할 것:
- **인접 색 병합**: k-means는 종이 톤의 밝은/중간/어두운 단계를 별개 색으로
  쪼갠다. 같은 계열이면 대표 하나로 합쳐 이름을 붙인다
- **이름 짓기**: `Archival Tan`, `Hot Red`처럼 역할이 드러나는 이름
- **개수 결정**: 2~5색. 억지로 채우지 않는다. 2색이면 2색으로 쓰고
  "strictly two-tone"을 규칙에 명시한다
- **역할 규칙(⑦)**: 가장 중요하다. 각 색이 **면을 채우는지, 선에만 쓰이는지,
  강조에만 쓰이는지** 관찰해 문장으로 쓴다
  - 예: `Red is reserved for strokes, underlines, and arrows; mustard is secondary accent only`
  - 이 문장이 없으면 생성 시 강조색이 배경 전체를 덮어버린다

### 4. 타이포그래피 (⑤) — 실제 문자열까지

이미지에 글자가 있으면 관찰하고, 없으면 스타일에 맞게 **창작**한다.

- 서체 성격: `condensed bold headline caps` / `technical lettering caps` / `clean geometric sans`
- 크기 위계: 헤드라인이 주인공인가, 라벨이 보조인가
- **샘플 문자열을 반드시 지정한다**. 시트에 그 단어가 그대로 인쇄되므로
  스타일을 대표하는 짧은 단어를 고른다 (`THE DEAL`, `ASSEMBLY VIEW`, `BUILDING BLOCKS`)
- 숫자 처리: 거대 숫자가 주인공인 시스템이면 그 샘플도 (`$123`, `142mm t0.5`)

### 5. 컴포넌트 (⑧) — 반복되는 부품 5~6개

이미지들에 **되풀이 등장하는 시각 부품**을 센다.

- 인물은 어떻게 처리되는가: 하프톤 컷아웃 / 실루엣 / 없음
- 가장자리 처리: 찢어진 종이 / 깔끔한 재단 / 둥근 모서리
- 강조 장치: 밑줄 / 화살표 / 원형 콜아웃 / 핀
- 데이터 표현: 카운터 카드 / 치수선 / 없음
- 액자·프레임: 흰 테두리 사진 카드 / 없음

### 6. 제작 논리 (⑨) — 이 시트의 심장

**모든 부품을 관통하는 한 문장.** "이 세계의 물건들은 전부 ___ 방식으로
만들어졌다"를 채운다.

- `halftone texture, offset stroke pop`
- `thin white ruled lines on blueprint blue, technical precision`
- `matte clay finish, soft rounded edges, gentle ambient occlusion, no hard speculars`

이 문장이 약하면 시트 전체가 무너진다. 부품 목록을 나열하는 게 아니라
**공통 제작 방식**을 뽑아내야 한다.

### 7. 모션 (⑪) — 정지 이미지에서 추론

정지 이미지에는 모션이 없다. 스타일의 물성에서 **추론**한다:

- 종이 컷아웃 → 스프링 팝업, 오버슈트, 종이 펄럭임
- 기술 도면 → 선이 그려지는 애니메이션, 부품 조립
- 클레이 → 스쿼시앤스트레치, 물리 흔들림, 턴테이블 회전

4개를 쓰되, DNA JSON의 `confidence.motion_signature`를 반드시 **low**로
표기한다 (추론이지 관찰이 아니다). 사용자가 영상 레퍼런스를 함께 주면
그때는 관찰로 격상한다.

### 8. THE STAGE (⑫) — 있을 때만

모든 장면이 **같은 배경 위에서** 벌어지는 시스템인가?

- 레퍼런스들의 배경이 서로 같은 계열이면 → THE STAGE 문단을 넣는다
- 배경이 장면마다 완전히 다르면 → **이 문단을 통째로 뺀다**

억지로 넣으면 배경이 고정돼 이후 클립들이 전부 똑같아 보인다.

### 9. 마감·금지 (⑬⑭) — 되지 말아야 할 것

관찰된 스타일의 **반대편**을 적는다.

- 무광 종이 스타일 → `no glossy 3D, no lens flares`
- 2색 도면 → `no color fills beyond the two-tone scheme, no glow effects`
- 부드러운 클레이 → `no hard speculars, no photorealism`

가장 흔한 실패 모드를 막는 문장을 최소 2개 넣는다.

## 마지막 점검

DNA를 다 채운 뒤 스스로 묻는다:

- [ ] 팔레트의 hex는 스크립트 값인가 (눈대중 아님)
- [ ] 색 역할 규칙(⑦)이 한 문장으로 쓰였는가
- [ ] 제작 논리(⑨)가 부품 나열이 아니라 공통 방식인가
- [ ] 한 장에만 있던 소재를 스타일로 착각하지 않았는가
- [ ] 타입 샘플이 실제 문자열로 지정됐는가
- [ ] THE STAGE가 정말 필요한가 (아니면 뺐는가)
- [ ] confidence에 추론한 항목(특히 모션)이 표기됐는가
