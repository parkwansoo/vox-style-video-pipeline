# 씬 설계 절차 — 4단계의 다단계 사고·검수 (v1, 2026-08-13)

클립 분할 설계를 "표 한 번에 뽑기"에서 **씬마다 여러 단계의 사고와 검수를
거치는 설계**로 바꾼 절차서다 (2026-08-13 사용자 지시). 기미 오일 편
씬 1~4에서 실제로 밟은 순서를 명문화했고, 이 편에서 검증 중이다.

**이 문서는 창의성 제약이 아니다.** 무엇을 그릴지는 전부 열려 있다 —
이 절차는 그 결정이 빠짐없이 내려졌는지, 내려진 결정이 물리적으로
성립하는지만 검사한다.

## 산출물 계층

```
plan.md            분할 표(seg 시각)·리텐션 검토·편별 적용 기록 — 편 전체
ch<N>/scenes/sceneNN.md   씬별 정본 — 확정 즉시 저장 (맥락 유실 방어)
```

화면·클립 구성의 정본은 **scenes/** 다. 눈검수에서 씬 하나가 바뀌면 그
파일만 고치고 즉시 저장한다. 프롬프트(영문)는 여기 쓰지 않는다 — 5단계가
씬 파일의 서술을 번역한다.

## 실행 방식 — 뼈대 합의 후 씬별 원패스 (2026-08-14 확정)

두 실패 모드를 함께 막는 구조다: 전편을 씬 하나씩 완성해 가면 체인 지도·
대구·리듬 같은 **전편 구조가 안 보이고**, 전체를 골격→상세 두 패스로
나누면 **패스 사이에 맥락이 끊긴다** (상세를 쓸 때 골격의 결정 이유를
잊고, 골격은 상세에서 드러날 문제를 모른다).

1. **전편 뼈대 먼저**: 13씬 전체의 경계 3형·체인 지도·기법 키·트림 수치·
   화면 개요(2~3문장)·위험을 뽑아 사용자와 **구조 방향을 합의**한다.
   뼈대는 검수용이지 최종본이 아니다 — 씬 파일에 `[뼈대]` 상태를 표기한다.
2. **그 다음 씬 하나씩 원패스**: 씬의 구조 재검증 + 이미지·영상 상세를
   **한 자리에서 한 번에** 완성한다. 상세를 쓰다 구조가 틀렸음을 발견하면
   그 자리에서 구조를 고치고, 체인 지도와 영향받는 이웃 씬 파일을 갱신한다.
   완성하면 `[상세완료]`로 바꾼다.
3. **씬 파일에는 결정과 이유를 함께** 남긴다 — 세션이 바뀌어도(대화 압축)
   파일만 읽으면 맥락이 복원되어야 한다. 공유 세계(인물·무대·색)는
   `scenes/공통설정.md`가 정본이다.
   **공통설정을 처음 쓰거나 크게 고칠 때는 활성 스타일 시트를 Read로 실제로
   열어 대조한다** (2026-08-14 도입 — 시트를 안 열고 쓴 공통설정이 "3층
   구슬 격자"처럼 시트에 없는 숫자를 만들었다). 대조 항목: ①시트에 있는
   요소(인물·소재·단면·무대)와 서술이 어긋나는 속성 ②숫자·개수·톤 형용이
   시트와 다르면 **그 서술을 지운다** — 시트가 단독 결정해야 컷이 일정하다
   (오일 수위 실측, CLAUDE.md "레퍼런스와 텍스트가 싸울 때") ③시트에 없는
   신규 무대·소품은 소재로 자유 ④**시트 속 인물과 주인공이 다르면** 인물
   앵커 이미지의 생성·검수를 게이트로 명시한다 (확정 후엔 앵커 ref가 시트
   인물 유출을 차단한다).
4. 눈검수는 씬 단위(또는 소묶음). 오래 걸려도 씬 단위로 확정하고 즉시
   저장한다.

## 절차 — 씬마다 7단계

1. **비트 분해**: 구간 대사를 정보 단위로 쪼갠다. **한 비트 = 한 정보.**
   비트가 2개 이상이면 컷을 나누거나(어절 경계) 인샷 장치로 내부를 쪼갠다.
2. **화면 결정**: 비트마다 "무엇이 보이는가"를 정한다. 직역을 넘어서
   은유·물체 변형(zdf-grammar 대원칙 5)을 먼저 검토한다.
3. **전환 선택**: 앞 씬과의 경계를 **클립 경계 3형**(원테이크 분배/체인/
   하드 컷)에서 고르고, 씬 내부 전환은 zdf-grammar의 **기법 키**로 지정한다.
4. **프레임·생성 결정**: 프레임 수(1/2), 생성 길이(4s/6s), 이미지별로
   생성인지 추출인지. 판단 기준은 아래 표.
5. **숫자 검증**: 구간 길이, 트림 가용 범위(배속 1.0~2.3x), 분할점이 어절
   경계인지, 원테이크면 비트 경계 여유가 있는지. **표를 만들었으면 반대
   방향(초과·미달)을 센다.**
6. **리텐션 심사**: `retention-review.md` 7항목 — 단, 씬 단위가 아니라
   **편 전체를 놓고 한 번** 돈다 (단조 구간·보상 배치는 씬 하나로 판정
   불가).
7. **저장**: sceneNN.md로 즉시 저장. 앞 씬 파일과 체인 관계가 어긋나지
   않는지 교차 확인.

## 판단 기준

| 결정 | 기준 |
|---|---|
| 체인으로 잇는다 | 연속된 설명 블록(같은 시각 세계의 전개), 카메라 여정이 정보인 컷 |
| 하드 컷으로 끊는다 | 화제 전환(접속사 "그래서/하지만"류), 훅 구간, **체인 블록이 3~4클립에 달했을 때**(순차 의존이 길어지면 병렬 생산이 죽는다) |
| 원테이크 분배 | 인접 두 씬의 구간 합 ≤ 생성 실효 길이(5.75s)이고 같은 카메라 여정으로 덮일 때. 비트 경계 여유를 5단계에서 계산 — 여유 0.1s 미만이면 위험 표기+폴백 명시 |
| 2프레임 | A→B 상태 변화가 메시지 자체일 때. end는 first를 ref로 첨부, 구도·거리도 함께 바꾼다 |
| 1프레임 | 물리적 움직임(낙하·흐름·표정)이 본체, AI 해석이 이득인 컷 |
| 슬라이드(생성 없음) | 단계적·비교형 변화 (prompt-checklist 슬라이드 절) |
| 생성 6s | 트림 자유가 필요한 대부분의 컷 (구간 3s 이상이면 사실상 필수) |
| 생성 4s | 구간 2.7s 이하 + 전환이 단순해 실패 위험이 낮은 컷 (크레딧 -3) |

## 씬 설계 체크리스트 — 씬 파일 저장 전에 통과

- [ ] 대사의 모든 정보 비트에 화면이 배정됐다 (버린 비트는 버렸다고 적었다)
- [ ] 한 컷이 두 정보를 말하지 않는다
- [ ] 앞 씬과의 경계 유형(3형 중 하나)과 씬 내부 기법 키가 지정됐다
- [ ] 스케일이 앞 씬과 같으면 그 이유가 있다 (zdf 대원칙 3: 전환=스케일 점프)
- [ ] **정지 컷이 아니다** — 카메라가 멈추면 인샷 장치(타임랩스·서브스크린·
      소품)가 대신 움직인다 (zdf 대원칙 4)
- [ ] 체인이면: 앞 씬 끝이 extension anchor인지, first가 "추출본, 재생성
      금지"로 명시됐는지
- [ ] 트림 가용 범위를 계산해 적었다 (사용 길이 min~max)
- [ ] 이미지 서술과 영상 서술이 분리돼 있고, 이미지는 프레임별로 구체적이다
- [ ] 화면 속 글자가 있으면: 이미지에 박는가(라벨·배지) / 영상 모션만
      허용하는가(큰 숫자) / 재그리기 금지인가 — 3분류를 지정했다
- [ ] 서술의 숫자·개수·톤 형용이 첨부될 ref(스타일 시트·SPEC·앵커)와
      어긋나지 않는다 — 어긋나는 서술은 지워서 ref가 단독 결정하게 한다
- [ ] 인물이 나오면 identity ref와 제외 목록을 지정했다
- [ ] 위험과 폴백이 적혀 있다 (실패하면 무엇으로 바꾸는가)

## 씬 파일 템플릿

```markdown
# 씬 N — 제목 (초안|확정 YYYY-MM-DD)
**대사** / **구간**: s~s (길이) | 생성 Ns | 프레임 1|2 | 기법 키
## 구성
- first/end: 생성(서술) 또는 추출(출처·명령)
- 영상: 카메라·모션·비트 시간 배분
- 트림: 사용 범위
## 위험·폴백 / 의존 관계
```

## 편 수준 마무리 검수 (전 씬 확정 후, 5단계 진입 전)

- [ ] 체인 블록 지도를 그렸다 — 블록별 순차 의존 길이와 병렬 가능성
- [ ] **제작대장을 작성했다** (`ch<N>/제작대장.md`) — 자산(이미지·추출
      프레임·영상)마다 ref 첨부·선행 조건·상태 체크를 한 표에. 씬이
      여러 이미지를 쓰고 끝 프레임이 다음 first가 되는 구조에서는 이
      대장 없이 순차 생성이 어긋난다. 5·6단계는 대장에서 선행 조건이
      전부 ✅인 자산만 만든다 (첫 사례: 기미 오일 편 2026-08-14)
- [ ] **검수용 엑셀을 생성했다** (`ch<N>/씬설계_검수.xlsx` — 씬개요·
      이미지·영상·공통설정 4시트, 대사는 전체 문장). 정본은 .md이고
      엑셀은 뷰다 — **씬 파일을 수정한 턴에는 같은 턴에 엑셀을
      재생성한다** (낡은 엑셀로 검수하게 만드는 것이 최악의 사고다).
      사용자 검수는 이 파일 중심으로 진행한다
- [ ] 크레딧 합계를 계산해 사용자에게 보고했다
- [ ] 리텐션 7항목을 편 전체로 돌았고 결과가 plan.md에 있다
- [ ] plan.md의 편별 적용 기록 표(씬/문장/기법 키)를 채웠다
- [ ] 씬 파일 간 체인 참조가 서로 모순되지 않는다 (A의 out을 B가 first로
      쓰는 관계가 양쪽에 같게 적혔는지)
